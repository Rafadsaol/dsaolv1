PROJETO CONCEITUAL · PORTFÓLIO · V3

Cidade do Sabor

Uma hamburgueria fictícia que conecta identidade gastronômica, cardápio interativo e operação demonstrativa em uma mesma experiência digital.

Ver imagens do projeto ↓Ver código no GitHub

Projeto conceitual, sem cliente real. As imagens mostram interfaces existentes; um clipe curto destaca apenas uma interação da aplicação original. Esta apresentação não executa a loja ou o painel da demo. Ainda não há link público para testar a aplicação interativa.

01 / CONTEXTO E PROPOSTA

Uma ideia explorada em interface.

O projeto explora o caminho da descoberta do cardápio à personalização e ao acompanhamento de uma simulação de pedido. A interface inclui uma área de gestão com perfis e dados de exemplo.

02 / IDENTIDADE VISUAL

Uma linguagem própria.

04 / INTERFACES EXISTENTES

O projeto, em detalhes.

Capturas de interfaces existentes: arquivos do repositório original e duas capturas mobile feitas na aplicação original em execução. Nenhuma interface foi inventada. Dados, valores e estados exibidos são exemplos. Abra cada imagem em uma nova aba para ampliar.

Experiência mobile

Duas telas reais do projeto, na mesma escala. Role dentro dos celulares ou amplie as imagens.

DETALHE EM MOVIMENTO

Uma troca de sabor, em movimento.

Um recorte da vitrine original mostra a transição entre os hambúrgueres. Imagem, texto e seleção do carrossel acompanham a troca, sem percorrer o restante do site.

Ao avançar o carrossel, a vitrine alterna entre Dupla da Cidade, Bacon Boulevard e Jardim Veggie; imagem, título e miniatura selecionada acompanham a transição.

Clipe de aproximadamente 8 segundos, sem áudio. Reprodução automática ao entrar na tela, com controles para pausar. A preferência por movimento reduzido mantém a reprodução manual. Baixar o clipe.

06 / ALCANCE DA DEMONSTRAÇÃO

Conceito com limites claros.

  • Não é um restaurante real nem um projeto entregue a cliente. Produtos, endereço, preços, depoimentos e dados comerciais são fictícios.
  • Perfis de cliente e administrador não têm autenticação real. Não há backend de operação, cobrança, envio ao restaurante ou reserva real de mesa.
  • Dados de teste ficam no navegador e não são compartilhados entre computador e celular. Alterações entre abas da mesma origem usam armazenamento local.
  • As capturas são de interfaces existentes; as imagens gastronômicas são identificadas no repositório como geradas por IA. Os indicadores nas telas são exemplos, não resultados comerciais.

O painel demonstrativo deste projeto é independente do painel protegido da dSaOl Web Studio. Nenhuma função deste estudo altera usuários, clientes ou projetos do backend da dSaOl.
